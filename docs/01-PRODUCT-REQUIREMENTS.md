# 01. Product Requirements (PRD)

0.4.0b2 client-candidate поставляет точный проверенный SDK API 8 для выбранных
native consumers без ручной установки. GUI постоянно сообщает границы одиночной
приёмки; multiplayer/dedicated не заявляются. Unknown native остаётся запрещён.
[ADR-0020](adr/0020-scoped-client-sdk-candidate.md).

Выбор новой локальной версии сохраняет identity существующего Workshop-мода:
галочка переключает версию, отказ восстанавливает прежнюю. Две версии одного
package не активируются вместе. [ADR-0021](adr/0021-explicit-package-version-selection.md).

Обновление общего SDK допускается только с exact reviewed previous runtime; backup и Undo обязательны. Built-in reviewed runtime удовлетворяет отсутствующую cc2x.runtime dependency. [ADR-0019](adr/0019-reviewed-runtime-upgrade-and-built-in-dependency.md).

Reviewed native profiles могут автоматически создавать отсутствующие SDK INI,
чтобы выбор мода давал эффект без ручного редактирования. Пользовательские
settings сохраняются; неизвестный DLL не получает этого разрешения.
[ADR-0018](adr/0018-reviewed-sdk-setting-defaults.md).

**Independent Lua modules:** один output сохраняет отдельные code roots и owner
IDs Bridge-модулей, выбранный порядок и зависимости. Manifest/code не сливаются
как overlays; shared game resources проходят обычный Git pipeline. Требуется
точный reviewed runtime с bundle capability. [ADR-0017](adr/0017-independent-lua-module-bundles.md).

**0.3.3:** распознаются игровые `.glsl` как UTF-8 text/Git resources и `.txtr` с TXTR magic как binary byte copy/whole-file replacement. Неизвестные типы не разрешаются молча; отказ показывает конкретный файл/причину. Shader compiler/TXTR decoder acceptance не заявлены. [ADR-0015](adr/0015-cc2-shaders-textures-and-actionable-refusals.md).

**0.3.2:** status=overridden оставляет предупреждение об участниках/ресурсе и неизвестном результате в игре, включая повторное открытие. Запуск не блокируется. Steam Required Items не считаются auto-installer. [ADR-0014](adr/0014-persistent-override-warning-and-workshop-delivery.md), [аудит Steam](19-STEAM-DISTRIBUTION-AUDIT.md).

**0.3.1:** пользовательское имя CC2 ModLoader и CC2ModLoader.exe; имя generated mod включает выбранные названия. Offline language pack покрывает 14 основных языков, по умолчанию system; новые language codes сохраняются без ручного конфига. [ADR-0013](adr/0013-modloader-brand-and-offline-language-pack.md).

**0.3.0, приоритет владельца:** редактируемый порядок выбранных пакетов автоматически пересобирает файлы и сохраняется. GUI по умолчанию разрешает явно описанный приоритет поздних патчей: Git отдаёт им спорные hunks, без оригинала происходит отмеченная замена целого data-файла. Локальные rom_0/SDK originals читаются без per-file hash allowlist; это заменяет прежний безусловный no-base запрет для этого режима. Сохраняются native/path/syntax/transaction gates. RU/EN следуют языку системы, выбранная вкладка крупнее соседних. [ADR-0012](adr/0012-user-ordered-patches-and-system-language.md).

**0.2.2:** отказ возвращает галочки к фактически применённому набору, а запуск прежнего рабочего набора доступен. Ошибка называет моды и ресурс; обязательные зависимости объясняют повторное включение. Основной экран содержит список и запуск, служебные действия — одно меню. mods/libraries под выбранной валидной игрой создаются автоматически при первом scan. [UX-аудит](18-UX-AUDIT.md), [ADR-0011](adr/0011-truthful-checkboxes-and-minimal-interface.md).

**Актуализация 0.2.1, 2026-11-02:** основной сценарий — «галочка → автоматическая проверка/слияние/включение → результат». Кнопки проверки/применения и подтверждение каждого набора отменены прямым запросом владельца. Output имеет постоянный путь `mods/CC2-MCE`, понятное имя в игре и заменяется целиком только после успешной проверки. При запущенной игре выбор ожидает её закрытия; при конфликте прежняя сборка сохраняется. Снятие всех галочек отключает моды. Undo восстанавливает payload и активацию. Этим уточняются прежние требования шагов 7/15 и явного подтверждения ниже. [ADR-0010](adr/0010-checkbox-auto-apply-and-stable-output.md).

## 1. Контекст и проблема

Carrier Command 2 не позволяет одновременно активировать моды, содержащие одинаковые игровые пути файлов, независимо от того, где находятся изменения. Существующий CC2X расширяет API Lua и поддерживает нативные плагины, но не даёт готового движка слияния файлов. Пользователь хочет собрать несколько модификаций без копирования и редактирования десятков файлов вручную.

## 2. Цель

Разработать **CC2 Mod Compatibility Engine (CC2-MCE)**: простое локальное офлайн-приложение с графическим интерфейсом для анализа и безопасного объединения правок в одном и том же пути игрового файла. Игрок выполняет весь сценарий в окнах и кнопках, без консоли, команд, ручной установки Python/Git/Lua и редактирования технических конфигов. Архитектура должна позволять в будущем заменить офлайн-упаковку динамической интеграцией с CC2X, но без привязки ядра к игре.

## 3. Пользователи и сценарии

- **Игрок:** открывает готовое приложение, отмечает установленные Workshop/локальные моды и получает отдельный локальный мод; видит простое объяснение, если выбранное сочетание нельзя безопасно объединить. Пользоваться терминалом, понимать SHA-256/JSON/Git или писать команды не требуется.
- **Разработчик мода:** получает diff своих изменений относительно vanilla/Mod SDK, отчёт с причиной конфликтов и воспроизводимый build manifest.
- **Мейнтейнер сборки:** обновляет моды, повторно запускает сборку и видит какие решения устарели.

## 4. Scope MVP (P0)

**MUST:**

1. Сканировать директории модов и строить индекс `game-relative-path -> [mod, source_path, sha256]`; автоматически искать Workshop-директории через конфиг/поиск Steam library с возможностью ручного override.
2. Определять кандидатов для слияния по **идентичному нормализованному игровому пути** (Windows-style casefold при сравнении, исходный регистр сохранять); ловить коллизии регистра и дубликаты.
3. Проверять, что исходная версия файла из Mod SDK соответствует ожидаемой игровой сборке; при неизвестной/неподходящей базе — **не строить** потенциально неверный merge.
4. Поддерживать простой текст (Lua `.lua`, `constants.txt` и иные разрешённые текстовые форматы) через готовый 3-way merge; не генерировать конфликтные маркеры в устанавливаемом пакете.
5. Поддерживать более двух модов; порядок слияния явно указан, стабилен и записан в отчёт; выявлять пересекающиеся изменения, включая конфликт delete-vs-edit.
6. Обнаруживать бинарные файлы, DLL и неизвестные типы и помечать их **unsupported/manual**, не делать побайтовый «merge».
7. Предоставлять действия «Найти моды», «Проверить сочетание», «Создать объединённый мод», «Сохранить отчёт» через GUI; показывать читаемое резюме, а машиночитаемый JSON-отчёт использовать внутри и для добровольного экспорта. CLI остаётся необязательным инструментом разработки/CI, не пользовательским интерфейсом.
8. Генерировать **только отдельный локальный мод** в staging, никогда не переписывать источники игры, Steam Workshop, vanilla или установленный CC2X.
9. Прекращать publish/install при unresolved conflicts; создавать пакет атомарно и безопасно повторять сборку.
10. Проверять кодировки, переносы строк, наличие конфликтных маркеров, для Lua — синтаксис поддерживаемой версии, для XML — well-formedness при XML-пайплайне.
11. Учитывать моды с `content/cc2x/*.dll`: помечать как требующие отдельного согласования, **по умолчанию блокировать**, не терять плагины незаметно.
12. Создавать manifest со списком модов, версиями/хешами исходников, build id и принятыми ручными решениями.
13. Поддерживать Windows и macOS как равноправные обязательные платформы пользовательского MVP: один графический сценарий, merge-правила, валидация, JSON-контракты и безопасная сборка в staging, без обязательной виртуальной машины, эмулятора Windows или CC2X. Минимальные версии ОС и архитектуры CPU утверждаются в M0; тесты/CI обязательны на обеих ОС.
14. Поставлять готовое настольное приложение для обеих ОС, запускаемое обычным способом без окна консоли. Все обязательные runtime/merge/validation инструменты включены в проверенную поставку; игрок не устанавливает их отдельно и не настраивает PATH. Пакет из исходников или wheel не считается пользовательской поставкой.
15. Обеспечить понятный сценарий «выбрать игру/папки → отметить моды → проверить → создать отдельный мод», автопоиск с безопасным выбором папки через системный диалог и сохранением настроек. Не требовать ручного TOML/JSON, хешей, baseline manifest или запуска команд; недостающая проверенная база остаётся блокировкой, не угадывается ради удобства.
16. Показывать пользователю прогресс, безопасную отмену, причины блокировок и конкретные следующие действия обычным языком. Детали/хеши/логи доступны отдельно; они не заменяют основной экран. Соблюдать доступность клавиатурой, читаемость и понятные состояния согласно [UX/UI](13-UX-UI.md).

**SHOULD (P1):** XML-aware merge по устойчивым ключам; расширенное ручное разрешение через KDiff3 из GUI; кэш результатов; повторное применение подтверждённых resolution с проверкой хешей. Базовый выбор модов в интерфейсе уже обязателен в P0.

**COULD (P2):** Lua AST-aware слияние; интеграция с CC2X/virtual filesystem; расширенные профили сборок; плагин-адаптеры типов ресурсов. Графический интерфейс не относится к отложенным возможностям.

## 5. Не-цели MVP

- Универсальная гарантия логической/игровой совместимости.
- Генерация пропущенной оригинальной версии по догадке или из модифицированного файла.
- Склейка двоичных ресурсов (mesh/audio/textures), DLL и хук-патчей.
- Изменение файлов Steam Workshop, `mods.xml` или запуска игры без отдельного согласия.
- Вмешательство в мультиплеер и автоматическое распространение локальной сборки другим игрокам.
- Обход проверки версии игры или поддержка VR/сервера CC2X по умолчанию.

## 6. Functional acceptance criteria

| ID | Условие | Проверяемый результат |
|---|---|---|
| FR-01 | Два мода редактируют разные строки одного Lua | Общий файл содержит обе правки, статус `clean` |
| FR-02 | Два мода задают разные значения одной строки | `conflict`, без installable output |
| FR-03 | Файл совпадает побайтно в двух модах | Одна копия, статус `identical` |
| FR-04 | У одного мода нет этого файла | Файл второго включён без merge |
| FR-05 | База отсутствует | Блокировка операции или явный `no-base`, не false-success |
| FR-06 | Бинарный файл изменён двумя модами | `unsupported_binary`, требует ручного действия |
| FR-07 | Файл был удалён и изменён | `delete_modify_conflict` |
| FR-08 | Мод содержит cc2x DLL | `native_plugin_review_required`, безопасный отказ по умолчанию |
| FR-09 | Повторная сборка тех же хешей/параметров | Побайтно одинаковый payload и стабильный manifest (исключая явно документированные метаданные времени) |
| FR-10 | Любой source-path выходящий за root | Запрещён, запись вне staging невозможна |
| FR-11 | Обновление одного исходного файла | Ранее сохранённый manual-resolution недействителен до проверки |
| FR-12 | Есть конфликтные маркеры в результате | Публикация запрещена, даже если процесс merge вернул 0 |
| FR-13 | Готовое приложение запускается на Windows и macOS из утверждённой матрицы | Один графический сценарий на обеих ОС без консоли и Windows-эмуляции; GUI smoke и unit/integration тесты проходят |
| FR-14 | Одинаковые байтовые входы, база, mod order, политики и версии инструментов на Windows/macOS | Совпадают статусы, конфликты и хеши payload; различаться могут только документированные сведения об окружении/времени и локальные пути |

| FR-15 | Чистая поддерживаемая ОС без Python/Git/Lua в PATH | Пользователь устанавливает/открывает готовое приложение и выполняет основной сценарий без команд и ручной установки зависимостей |
| FR-16 | Игра или папка модов не найдена автоматически | Системный выбор папки, понятная проверка и сохранение настроек; нет ручного ввода команд/конфигов |
| FR-17 | Конфликт, нет проверенной базы, DLL, неверный формат или отсутствует встроенный инструмент | Понятная причина и безопасное следующее действие; создание недоступно, нет «игнорировать и продолжить» |
| FR-18 | Долгая проверка, отмена или изменение выбора/источников | Окно отзывчиво, прогресс виден, отмена безопасна; устаревшее резюме не разрешает сборку |
| FR-19 | Полный пользовательский сценарий и экспорт отчёта | Всё через GUI; технические подробности необязательны, экспорт только по явному действию без публикации личных путей |
| FR-20 | Клавиатура, экранный диктор, масштабирование интерфейса | Все основные действия доступны; состояния имеют текст, не обозначаются только цветом/иконкой; кнопки и сообщения не обрезаны |

## 7. Нефункциональные требования

- **Safety-first:** ни одна штатная операция не должна портить пользовательские файлы, моды и игровой SDK.
- **Прозрачность:** для каждого выходного файла можно определить источники и алгоритм обработки.
- **Воспроизводимость:** фиксированные входы + конфиг + версия движка + политики дают одинаковый payload.
- **Testability:** merge-ядро без Steam/игры, все edge cases — в юнит-фикстурах.
- **Extensibility:** форматные обработчики подменяются через интерфейс `MergeStrategy`.
- **Мультиплатформенность:** Windows и macOS — обязательные платформы всего графического приложения, не только ядра; установка, runtime-зависимости, GUI, пути, subprocess и staging проверяются на обеих ОС. ОС запуска CC2-MCE не определяет целевую сборку игры: baseline всегда проверяется для выбранной игры. Поддержка приложения на macOS не означает поддержку CC2X или подтверждённый запуск самой CC2 на macOS.
- **UX:** терминал не входит ни в один пользовательский сценарий, включая настройку, ошибки, экспорт и восстановление. Основной экран без технического жаргона, длинные задачи не блокируют окно. Изменения подтверждаются явно; проверка без записи и понятный rollback доступны через интерфейс. См. [обязательные UX-критерии](13-UX-UI.md).

## 8. Метрики

- Доля *ложных файловых конфликтов*, автоматически разрешённых на утверждённом наборе модов.
- Число ложных `clean` (цель: **0 на золотом тестовом наборе**, не абсолютная гарантия вне него).
- Воспроизводимость: 100% совпадений output-hash на повторных запусках одинаковых fixtures.
- Актуальность baseline: 100% сборок указывают источник, хеш и версию базы.
- Пользовательский сценарий: 0 обязательных консольных команд, ручных установок runtime-инструментов и редактирований технических конфигов; полный проход на чистых Windows/macOS и с пользователем без инструкций разработчика обязателен перед релизом.

## 9. Статус

**0.2.0, 2026-11-01:** Windows GUI pipeline создаёт отдельный mod package и явно применяет его к игре с backup/rollback, включает проверенные Git/Lua tools, SDK library metadata/dependencies и reviewed native copy. Реально проверен запуск AI Bridge + Island Airfields и загрузка DLL из combined package. Это заменяет ограничения создания/активации прототипа ниже; общие Windows/macOS/gameplay release gates не объявляются завершёнными. [ADR-0009](adr/0009-package-activation-and-library-sdk.md).

Текущий GUI-прототип находит игру/Workshop через Steam metadata и соседний executable, читает локальные `mods` и отдельные Lua/DLL-пакеты `libraries`; Windows portable требует exe рядом с игрой. Границы: [ADR-0008](adr/0008-portable-discovery-and-library-collections.md). Это не завершённый MVP: runtime, verified baseline preparation, publish/staging и Windows/macOS release gates открыты. Ниже описан исторический первый срез.

Требования описывают целевой MVP, а не гарантию уже работающей функциональности. Первый срез 0.1.0.dev1 реализует read-only discovery и dry-run merge/report на синтетических входах; GUI/готовая пользовательская поставка, packaging, replay plan и игровые acceptance gates не реализованы/не пройдены. CLI-first больше не определяет пользовательский MVP ([ADR-0007](adr/0007-gui-first-user-experience.md)). Сценарии с реальными модами и доступность оригиналов проверяются на Milestone 0; см. [статус M0](12-M0-VALIDATION.md).
