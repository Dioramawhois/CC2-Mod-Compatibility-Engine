## 2. Открытые вопросы (не скрывать под видом решений)

1. **Какой реальный формат/обязательные поля `mod.xml` у локальных модов 1.5.18?** Проверить на готовом примере в установленной игре.
2. **Как сопоставляются файлы `mod_dev_kit` и runtime `content/` для всех типов?** Нужен verified resolver, а не filename guessing.
3. **Все ли нужные ванильные Lua доступны в поставке SDK актуальной сборки?** Проверить список и хеши.
4. **Нужно ли сохранять все метаданные исходных модов в output?** Уточнить для локального профиля и прав автора.
5. **Какие ресурсы содержат смешанные кодировки?** Собрать статистику и подготовить валидаторы.
6. **Нужно ли на v1 безопасно переносить уникальные файлы `.dll` из CC2X модов?** По умолчанию запрещено, research после M2.
7. **Как именно CC2X обрабатывает plugin_dir при переносе DLL в merged mod?** Проверка in-game и исходного SDK.
8. **Насколько CC2X `dinput8.dll` и игра версии 1.5.18 актуальны для всех целевых пользователей?** Включить версионирование и guard.
9. **Решено: GUI обязателен в первой пользовательской версии на Windows/macOS.** Ни команд, ни ручной установки инструментов для игроков. Открыт только выбор toolkit/упаковщика после практического spike ([ADR-0007](adr/0007-gui-first-user-experience.md)).
10. **Лицензия самого CC2-MCE?** Решение владельца перед публичным репозиторием.
11. **Какие минимальные версии Windows/macOS и архитектуры CPU поддерживать?** Обе ОС обязательны; конкретную runtime-матрицу и наличие Python/Git/Lua 5.3 validator проверить в M0. Доступность самой CC2/SDK и игровой запуск на macOS подтверждаются отдельно, не выводятся из поддержки CLI.

## 3. Никаких ложных гарантий

Статус `clean` означает: diff3 не нашёл неразрешённых текстовых конфликтов, валидаторы приняли результат. **Он не означает:** «сработают обе механики», «сеть не рассинхронизируется», «DLL совместимы», «автор модов разрешил публикацию merged сборки». Документация/UI должны различать эти утверждения.
