# ADR-0010: Галочка сразу обновляет одну постоянную сборку

**Уточнение 0.2.2:** [ADR-0011](0011-truthful-checkboxes-and-minimal-interface.md) требует возвращать отклонённый выбор к applied составу, объяснять отказ у строки, сохранять доступность рабочего набора и готовить папки автоматически. Pending selection по-прежнему блокирует launch до результата/закрытия игры.

- **Статус:** Accepted по прямому запросу владельца.
- **Дата:** 2026-11-02.
- **Уточняет:** ADR-0007/0008/0009 в части интерфейса, имени output и подтверждения записи.

## Решение

1. Основной сценарий: открыть → поставить/снять галочки → увидеть результат → запустить игру. Галочка является явным действием применения. Отдельных кнопок проверки/применения и дополнительных подтверждений нет. Требование ADR-0009 о подтверждении каждого набора заменено этим запросом владельца.
2. Постоянный output: пользовательский `Carrier Command 2/mods/CC2-MCE`. В игре он называется «CC2 Engine — мои моды». Хеши и build_id остаются внутренними полями manifest, не именами пользовательских папок/строк списка.
3. Проверка выполняется в фоне после 250 мс без новых переключений. Результат устаревшего выбора не может начать публикацию. Во время короткой записи выбор/закрытие защищены. Строка фактической активации отделена от желаемых галочек; запуск неприменённого набора блокируется.
4. Обновление выбранных исходников автоматически обнаруживается повторным bounded scan раз в 3 секунды, когда приложение свободно. Выбор сохраняется. Новый найденный мод появляется в списке, но не включается без галочки. Исчезнувший выбранный мод остаётся строкой, которую можно снять; молчаливого удаления из набора нет.
5. Запущенная игра не изменяется. Выбор ожидает закрытия игры и затем применяется автоматически. Конфликт/нет базы/неизвестная DLL/ошибка проверки сохраняют прежнюю рабочую сборку; небезопасного fallback нет.
6. Снятие последней галочки публикует пустой payload и очищает active_mod_folders. В manifest `mod_order` может быть пустым; runtime автоматически не удаляется.
7. Сначала создаётся и проверяется полный stage в служебном `cc2-mce`, затем под OS lock прежняя собственная папка переносится в backup, stage получает постоянное имя и записывается активация. Новая папка не накладывается поверх старой: удалённые из набора файлы не остаются.
8. Перед перемещениями записывается pending journal. Ошибка или прерывание процесса восстанавливает прежнюю папку и config; после прерывания восстановление выполняется перед следующей записью. Чужая/изменённая папка не перезаписывается. Все перемещаемые пакеты сверяются по manifest и точному inventory/hash, без запуска Lua/DLL.
9. Undo восстанавливает и прежние байты payload, и mods.xml. Повторный запуск с тем же build_id не затирает предыдущий undo, включая известное форматирование XML игрой. Предыдущие неактуальные резервные payload удаляются только из проверенного служебного каталога.
10. Старые собственные hash-папки, включая неактивные, переносятся в служебный cache только после полной проверки manifest/inventory; undo возвращает их на прежние места. Workshop, vanilla, SDK и неизвестные outputs не меняются. Generated outputs исключены из discovery.

## Контракты и проверки

Schema v2 обратно совместимо допускает `output_folder: "CC2-MCE"` и пустой `mod_order`; старые v2 manifests читаются для миграции. Provenance и все прежние fail-closed gates сохраняются. CLI v1 не меняется.

Regression fixtures: повторная замена/obsolete-file removal, empty set, unknown output, config failure, interrupted rename recovery, hash-folder migration, idempotent restart/undo; реальные Tk widgets — автоматическая галочка, быстрые изменения, конфликт, game-running wait, source update. Эти проверки не являются flight/AI gameplay или macOS execution acceptance.
