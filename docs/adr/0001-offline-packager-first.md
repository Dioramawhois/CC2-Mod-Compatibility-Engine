# ADR-0001: Офлайн-пакетирование прежде CC2X hooks

- **Статус:** Accepted для офлайн-упаковки; CLI-first пользовательский интерфейс заменён обязательным GUI в [ADR-0007](0007-gui-first-user-experience.md)
- **Дата:** 2026-10-25

## Контекст

CC2 запрещает одновременную активацию модов, заменяющих одинаковые файлы. CC2X предоставляет нативные hooks, но resource-level перехват и устранение внутренних file collisions не подтверждены. Ранний DLL integration увеличивает цену ошибок.

## Решение

MVP — внешнее офлайн-приложение: `scan -> plan -> merge -> validate -> stage -> (manual install)`. Создаётся один локальный merged mod, оригиналы не меняются. Доменное merge-ядро не зависит от интерфейса, Steam и CC2X. Первоначальный CLI-first уточнён [ADR-0007](0007-gui-first-user-experience.md): пользователь работает только через GUI, CLI допустима лишь разработчикам/CI; модель офлайн-упаковки не изменена.

## Последствия

+ Быстрее сделать и тестировать, меньше risk для игры.
+ Используем стандартные текстовые merger.
- Нужно отключать исходные конфликтующие моды, иначе штатное меню видит file collisions.
- Нативные CC2X plugins у отключённых модов пропадут; поэтому `native_plugin_review_required` блокирует package до отдельного решения.

## Альтернативы

- Перехват resource loading в CC2X — отложен до M5.
- Прямая запись в Steam Workshop — отвергнута как unsafe.
