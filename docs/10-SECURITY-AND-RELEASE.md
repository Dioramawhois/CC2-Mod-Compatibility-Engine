# 10. Security, эксплуатация и релиз

## 1. Модель угроз

Инструмент читает **недоверенные пользовательские моды**, а затем создаёт пакет, который игра может исполнять как Lua или native DLL. Главные риски: обход sandbox через пути/симлинки, XML external entities, огромные/специально подготовленные файлы, произвольный код через DLL, неконтролируемые вызовы subprocess, повреждение модов/сохранений.

## 2. Обязательные меры

- Использовать pathlib + strict canonical path validation; относительный игровой путь не может выходить за `content/`. Отвергать UNC, drive prefixes, NUL, `..`, Windows reserved names, symlink/junction escape.
- Не вызывать `shell=True` и не вставлять пути/имена модов в shell-команды; `subprocess.run(list_of_args, ...)` с timeout, ограничениями файлов.
- `git merge-file -p` работает с копиями в temp; не передавать оригинальные пути как in-place output.
- Не исполнять/не импортировать Lua при проверке — `luac -p` только проверка синтаксиса; никогда не загружать стороннюю DLL в процесс CC2-MCE.
- Для XML отключить DTD/XXE, сетевые разрешения и entity expansion.
- Ограничивать max scan depth, max files, max bytes, темпы хеширования, сообщать об отказе.
- Проверять input hash до и после операции, особенно Workshop.
- Писать staging на том же диске с output; atomic move/replace только в собственный managed directory, с versioned rollback.
- Никогда не переписывать Steam Workshop, game executable, SDK, mods.xml и dinput8.dll в MVP.
- Не связывать ошибку валидации с автоматическим fallback `last mod wins`.

## 3. Конфиденциальность/отчёт

Отчёты могут раскрывать имя пользователя Windows/macOS и пути установленных программ. В режиме экспорта пути редактируются/делаются относительными. Не записывать секреты из содержимого модов в общественный issue. Список SHA-256 может раскрывать состав локальной сборки: включать сознательно.

## 4. Native DLL trust

CC2X-совместимые моды могут выполнять native code в игровом процессе. Сборка из чужих DLL не делает их безопасными. По умолчанию выводить plugin review required. Явный opt-in в будущем — только после анализа источника, версии архитектуры x86, имён DLL, правил path/config, patch overlap, лицензии и одобрения пользователя.

## Ограничения защиты первого среза

0.1.0.dev1 не пишет payload/пакеты и не редактирует источники. Отчёт создаётся только новым файлом вне входных корней; публикация/atomic install/rollback ещё не реализованы. Чтение ограничено бюджетами, ссылки/junction и неоднозначные пути отклоняются, снимки хешей перепроверяются; это не полная защита от всех конкурентных directory races. Не запускать scanner на активно изменяемых недоверенных каталогах с ожиданием sandbox-гарантий. Subprocess timeout действует на Git/Lua; JSON-вывод не включает содержимое mods и личные host-пути по умолчанию.

## 5. Release checklist

- [ ] Release notes соответствуют реализованным функциям, не спецификации будущего.
- [ ] Пользователь получает готовое графическое приложение Windows/macOS, не исходники/wheel/CLI; чистая ОС без Python/Git/Lua и developer tools проходит полный сценарий без терминала и консольных окон.
- [ ] Runtime/backend/validator включены и проверены для каждой ОС/архитектуры; подпись/доверие ОС и лицензии поставки подтверждены, нет инструкций отключать защиту или обходить её командами.
- [ ] GUI/e2e и usability walkthrough пройдены: выбор каталогов/модов, понятные blockers, прогресс/отмена, актуальность плана, создание/экспорт/восстановление, клавиатура/диктор/масштаб. См. [UX/UI](13-UX-UI.md).
- [ ] CLI smoke, unit/integration/format tests + golden fixtures прошли на Windows и macOS; проверено совпадение статусов, конфликтов и хешей payload при одинаковых входах/инструментах.
- [ ] Опубликованы минимальные версии Windows/macOS, архитектуры CPU и инструкция обычной установки/открытия приложения; игрок не устанавливает Python/Git/Lua validator. Staging/rollback проверены на обеих ОС.
- [ ] Game build/Mod SDK/CC2X versions опубликованы как compatibility matrix отдельно от host-матрицы CC2-MCE; поддержка macOS CLI не выдаётся за поддержку CC2X или непроверенного игрового runtime.
- [ ] Проверены формат mod.xml, активация единственного merged mod, rollback.
- [ ] Никаких unresolved conflict markers в package.
- [ ] Полный file list и sha256 источников/выходов включены в manifest.
- [ ] SBOM/NOTICE для вендорного кода/зависимостей, license compliance проверена.
- [ ] Нет включённых файлов игры и чужих модов без разрешения.
- [ ] Проверены security tests и path traversal.
- [ ] Опубликованы known limitations (binary/DLL/multiplayer/semantic risk).
- [ ] Есть инструкция deactivation/uninstall и восстановление исходной конфигурации.

## 6. Совместимость версий

Version guard: если fingerprint игры отличается от проверенных build IDs, GUI объясняет причину и следующее действие (внутренний CLI возвращает тот же blocker), офлайн scan возможен, installable merge при неподтверждённом baseline не создаётся. Для bridge плагина CC2X — ещё более строгий guard по `api_version`/game build.
