# ADR-0011: Галочки отражают применение, отказ отменяет изменение

- **Статус:** Accepted по запросу владельца от 2026-11-02.
- **Версия:** 0.2.2.
- **Уточняет:** ADR-0008 (подготовка папок), ADR-0010 (состояния выбора и отказа).

## Проблема

0.2.1 сохраняла прежние файлы при конфликте, но оставляла новое сочетание отмеченным. Пользователь воспринимал галочку как включение; фактическая активация расходилась с экраном, а запуск рабочего набора блокировался. Общая ошибка без участников и многочисленные служебные кнопки ухудшали восстановление. [Аудит](../18-UX-AUDIT.md).

## Решение

1. Сохранять отдельный снимок фактически применённых ID. Во время проверки/ожидания галочки являются временным запросом с явным состоянием строки; launch отключён. Только успешный commit меняет снимок.
2. Любой окончательный отказ (конфликт, no-base/native/validation/tool error, ошибка применения) возвращает весь выбор к последнему применённому набору и отменяет отложенный запрос. Новая галочка снимается. Если рабочая активация известна и нет pending transaction, её можно запустить сразу.
3. Отказ не выбирает победителя и не выключает работавший мод ради нового. Banner называет отклонённый мод и участников; причина остаётся рядом со снятой галочкой. Подробности содержат путь ресурса, доступны через меню; непрошедший plan можно экспортировать.
4. Если изменились исходники включённых модов, отказ оставляет их прежний активный payload и сообщает об этом. Пассивный scan и появление неотмеченного мода не стирают ошибку и не повторяют отклонённый выбор. Пересборку вызывает изменение выбранных sources, а не любой неотмеченный пакет.
5. Если снятая зависимость нужна выбранному моду, resolver включает её обратно с явной причиной «Требуется для …». Это не конфликт; молчаливого возврата галочки без объяснения нет.
6. Первый scan выбранной валидной игры автоматически и идемпотентно создаёт только её mods/libraries. До portable placement записи нет. Существующий файл, junction или недоступный каталог не заменяется/обходится; отображается понятная ошибка. Отдельной кнопки подготовки нет.
7. Главный экран содержит компактный статус, моды/библиотеки, inline результат и «Запустить игру». Поиск/выбор игры/дополнительная папка/пути/undo/export/подробности находятся в одном меню. Пути и SDK packaging instructions убраны с основного экрана. Прогресс показан только во время операции.
8. Строки имеют текстовые состояния «Включён», «Выключен», «Проверяем», «После закрытия игры», отказ/зависимость; цвет только дополняет текст. На старте включённые моды показаны первыми, остальные по имени; во время клика список не прыгает. Работают колесо и клавиатурные галочки.

## Контракты и доказательства

Package schema v2 и merge/core правила не меняются. Rejected report описывает отклонённый запрос, а не текущую активацию; UI держит эти состояния отдельно. Новый `ui_feedback` — чистое представление структурированного отчёта, не новый merger. Все provenance/hashes, source isolation, closed-game gate, transactional single output и undo сохраняются.

Regression fixtures используют настоящий Git и реальные Tk widgets: конфликт/ошибка записи возвращают галочки; рабочий набор запускается; названы участники/ресурс; passive scan не стирает отказ; зависимость объясняет повторное включение; папки создаются автоматически, файл на их месте сохранён; служебных кнопок на главном экране нет. Synthetic screenshot отдельно помечен как synthetic, не gameplay. Windows frozen GUI и установленный набор проверяются отдельно; macOS execution/accessibility/clean-machine gates не объявляются завершёнными.
