# ADR-0005: Windows и macOS — обязательные платформы офлайн-приложения

- **Статус:** Accepted; GUI и пользовательская поставка уточнены [ADR-0007](0007-gui-first-user-experience.md)
- **Дата:** 2026-10-25

## Контекст

Первоначальная спецификация называла Windows целевой платформой, а кроссплатформенность ядра — желательной. Владелец проекта требует обязательной поддержки Windows и macOS. Поддержка только ядра или запуск CLI через Windows-эмуляцию этому требованию не соответствует.

CC2-MCE — офлайн-утилита, независимая от игрового процесса. Windows-only ограничения CC2X не должны ограничивать её host-платформы; доступность самой CC2 и Mod SDK на macOS требует отдельного подтверждения.

## Решение

1. Windows и macOS — равноправные обязательные host-платформы MVP для готового графического приложения, discovery, merge, валидации, отчётов и безопасной сборки в staging. Виртуальная машина, эмулятор Windows, CC2X и консольные действия игрока не обязательны. Пользовательский сценарий — только GUI ([ADR-0007](0007-gui-first-user-experience.md)).
2. В M0 утвердить минимальные версии ОС, архитектуры CPU и совместимые версии Python, Git и Lua 5.3 validator; пользовательская поставка включает проверенные инструменты, ручная установка зависимостей относится только к разработке. Пока матрица не проверена, не заявлять реализованную поддержку.
3. Платформенные пути, поиск Steam/инструментов и операции файловой системы изолировать в адаптерах. Нельзя требовать Windows API/registry в общем pipeline. Пользователь может явно указать доступные каталоги модов и подтверждённой базы целевой игры независимо от host-ОС.
4. CLI, коды завершения, JSON-контракты и fail-closed политики одинаковы на обеих ОС. Игровые пути используют `/` и единые правила сравнения; неоднозначные коллизии регистра/Unicode блокируются. Host-пути обрабатываются отдельно.
5. При одинаковых байтовых входах, базе, порядке модов, политиках и версиях инструментов статусы, конфликты и хеши payload совпадают. Различия локальных путей, окружения и времени допустимы только как документированные метаданные, не изменения payload.
6. CI и release gates включают обе ОС: CLI smoke, unit/integration/format, path/case/Unicode/EOL fixtures и staging/rollback. Игровые тесты проводятся отдельно на подтверждённой целевой игровой платформе.
7. Поддержка macOS CLI не означает поддержку CC2X, Windows DLL или нативной CC2 на Mac. Неизвестный baseline, неподтверждённый пакет или DLL продолжают блокировать соответствующую операцию; мультиплатформенность не ослабляет safety gates.

## Последствия

+ На Windows и Mac доступен один офлайн-workflow без обязательной привязки к игровому процессу.
+ Одинаковые контракты и fixtures выявляют платформенные расхождения до релиза.
- Нужны две CI-среды и проверка зависимостей/файловой системы на каждой поддерживаемой архитектуре.
- Подтверждение host-поддержки и игровой совместимости ведётся раздельно; непроверенные игровые сценарии остаются явно неподтверждёнными.
