# ADR-0012: Порядок патчей, локальные оригиналы и системный язык

- **Статус:** Accepted по прямым запросам владельца 2026-11-02.
- **Версия:** 0.3.0.
- **Заменяет:** прежний запрет data merge без заранее одобренного file hash и запрет явно выбранного приоритета в ADR-0003/0009. Native/path/syntax/transaction safety сохраняется.

## Порядок и приоритет

1. Вкладка «Порядок загрузки» показывает фактическую последовательность выбранных модов/библиотек. Drag/drop и Alt+↑/↓ меняют её и автоматически пересобирают output. Порядок сохраняется в настройках и mod_order; restart восстанавливает активную последовательность. Зависимости размещаются перед зависимым пакетом.
2. Основной GUI по запросу владельца использует `ordered-patches`. При известном оригинале сначала выполняется настоящий Git three-way. Пересекающиеся hunks разрешаются Git `merge-file --theirs` в пользу позднего патча; независимые изменения ранних модов сохраняются. Отдельный результат `overridden` и strategy записывают такое решение.
3. Оригинал берётся из установленного rom_0, иначе из mod_dev_kit/source, без hard-coded списка разрешённых файлов. Относительный baseline_source и настоящий SHA сохраняются; обновление перед apply выявляется повторным analyze. Непрофилированная сборка допускает data merge, но не получает native approvals.
4. Если оригинала действительно нет, three-way не выдумывается: последний файл в выбранной последовательности заменяет прежние целиком (`ordered-replacement-no-base`). Разные известные binary resources могут явно заменяться по порядку (`ordered-binary-replacement`), не сливаются побайтно. GUI показывает число замен. MZ/DLL в любом участнике не становится разрешённым по этому режиму.
5. Приоритет включён в GUI по умолчанию; его можно отключить в меню для строгой проверки. Developer merge/core default остаётся strict. `merge_policy` фиксируется в package report v2 и воспроизводится при повторной проверке apply. Повторная поздняя версия, совпадающая с ранней, сохраняет свой поздний приоритет.
6. Lua syntax/UTF-8/path/junction/лимиты, неизвестные типы и native approval не обходятся. Отказ возвращает предыдущие галочки/порядок; рабочая сборка сохраняется. Наличие формально валидного результата не является гарантией игровой логики.

## Язык и интерфейс

7. Поддержаны RU/EN, по умолчанию `system`: Windows UI language, остальные hosts — locale; неподдержанный язык использует English. Меню позволяет выбрать System/Русский/English. UI strings, feedback и engine diagnostics локализованы; имена авторских модов/пути не переводятся.
8. Смена языка сохраняется атомарно и пересоздаёт окно после завершения текущей записи/worker, сохраняя активную сборку. Pending checkbox/order request переносится в новое окно и продолжает ожидание закрытия игры. Locale не влияет на payload/build identity; игровое имя output — нейтральное «CC2 Engine».
9. Preferences schema 1 содержит owner, language, patch_priority, orders по game root, extra_roots. Файл ограничен 64 KiB, atomic replace сверяет предыдущие байты, постороннее изменение не затирается. Игрок не редактирует конфиг.
10. Выбранная вкладка имеет больший padding и жирный заголовок; state map явно переопределяет clam theme. Это устраняет меньший размер выбранной вкладки.

## Контракты и проверки

Package schema v2 обратно совместимо дополнена optional merge_policy и file.baseline_source; status `overridden` отличает приоритет от clean. Source/base/engine/output hashes и порядок обязательны. CLI report v1 не меняется.

Regression fixtures: смена порядка меняет спорные hunks и сохраняет независимые; отсутствие оригинала не создаёт fake base; строгий режим блокирует; поздний повтор раннего файла сохраняет приоритет; apply воспроизводит policy; GUI drag model автоматически перестраивает и сохраняет порядок; RU/EN/system, переменные в сообщениях, catalog coverage, preferences/race и размер выбранной вкладки. Реальный read-only plan с Revolution 1.6-19 дал 41 resource, 4 override и 0 blockers; это не game acceptance.
