## 1. Обещание пользователю

0.2.0 реализует Windows путь «выбрать → проверить → применить к игре → запустить», actual activation header, автоматические зависимости библиотек, backup/restore и export отчёта. Смена выбора аннулирует план; launch не выдаёт неприменённый выбор за включённый. Во время commit выбор/закрытие окна защищены от прерывания. Исторические сообщения «создание отключено» ниже относятся к прототипу, не новой проверенной Windows ветке. Общая доступность/clean-machine/macOS приёмка остаётся обязательной. [ADR-0009](adr/0009-package-activation-and-library-sdk.md).

Реализованный discovery-прототип: игра определяется по соседнему exe и Steam libraries; Windows portable показывает требование переноса exe к игре. Моды из Workshop и `mods` показаны в одной вкладке с происхождением, пакеты Lua/DLL из `libraries` — в другой. Кнопка «Подготовить папки» создаёт только эти два каталога. Создание игрового пакета отключено; это не полная приёмка сценария ниже. См. [ADR-0008](adr/0008-portable-discovery-and-library-collections.md).

**Открыть приложение → выбрать моды → проверить → создать отдельный мод. Никакого терминала.**

Приложение для обычного игрока, не для разработчика. Не требуется знать Git, Lua, JSON, SHA-256, понятия baseline/staging/dry-run, устанавливать Python/инструменты, настраивать PATH или писать конфиги. CLI остаётся только у разработчиков и CI. Нельзя предлагать команду как «простой способ» установки, исправления ошибки или восстановления.

Windows и macOS получают одинаковый сценарий, с привычными для ОС файловыми диалогами и поведением окна. Пользователь скачивает готовую сборку для своей ОС/архитектуры, устанавливает/переносит обычным способом и открывает ярлык или приложение. Нет окна консоли, локального сервера, ручного запуска служебного процесса или обязательного аккаунта/сети. Технический стек GUI ещё не выбран: отдельный implementation spike должен подтвердить упаковку, доступность и лицензии на обеих ОС, не ослабляя требования.

## 2. Первый запуск и настройка

- Заголовок «Объединение модов Carrier Command 2», одна основная кнопка «Начать»; короткое пояснение «Оригинальные моды останутся без изменений».
- Автопоиск игры, модов и доступных оригинальных файлов. Результат показывается человеку; не найдено или найдено несколько установок — «Выбрать папку игры» / «Добавить папку модов» через системный диалог, затем проверка выбора.
- Папку SDK при необходимости выбирают таким же диалогом. Приложение само проверяет версию, mapping и хеши по подтверждённым правилам; игрок не составляет baseline manifest и не вводит хеши. Неподтверждённая база остаётся блокировкой, а не «похоже, подходит». Пока проверенный mapping не поддержан — анализ доступен, создание запрещено.
- Настройки каталогов сохраняются в собственном пользовательском каталоге приложения, не в игре/Workshop. При повторном запуске пути и доступ проверяются заново. Нет ручного редактирования TOML/JSON и обязательных administrator-прав.
- Проверка встроенных инструментов выполняется автоматически. Проверенные Python runtime, Git backend и Lua 5.3 validator поставляются с приложением для поддерживаемой ОС/архитектуры. Отсутствующий компонент — ошибка поставки с действием «Проверить снова» / «Открыть справку», а не инструкция установить Git или выполнить команду. Нельзя молча подменить Lua 5.3 другой версией.

## 3. Основное окно

Минимальная структура, не обязательный визуальный стиль:

```text
Объединение модов                  [Настройки]
Игра найдена / Нужна настройка     [Изменить папку]

Выберите моды                     [Поиск по названию]
[ ] Название мода · Автор · Workshop/локальный
[ ] Название мода · Автор · Workshop/локальный
    Выбрано: 2                    [Обновить список]

[Проверить сочетание]
Результат проверки — здесь
[Изменить выбор]                   [Создать объединённый мод]
                                  [Подробности] [Сохранить отчёт]
```

- Названия/авторы важнее числового Workshop ID и пути; если metadata нет — нейтральное «Мод без названия» и различимый источник в подробностях. Поиск, пустой список и ошибка доступа имеют отдельные сообщения.
- Моды не выбираются все автоматически. Показываются выбранные участники и воспроизводимый порядок; порядок не объявляется приоритетом и не разрешает конфликты по принципу «последний победил». Продвинутую настройку порядка можно вынести в подробности.
- «Проверить сочетание» доступна при осмысленном выборе и валидных каталогах. «Создать объединённый мод» доступна только для актуального полностью проверенного плана без blockers и при реально реализованной/подтверждённой упаковке.
- Изменение выбора, порядка, каталогов или обнаруженное обновление файлов сбрасывает готовность: «Выбор изменился — проверьте снова». Нельзя создать сборку по устаревшему зелёному экрану.
- Недоверенные названия и описания показываются как текст: не исполняются как HTML/ссылки/команды; длинные строки не ломают интерфейс.

## 4. Проверка: обратная связь и сообщения

Окно остаётся отзывчивым. Видны этап («Ищем моды», «Сравниваем изменения», «Проверяем файлы»), объём обработанного при наличии достоверного счётчика и кнопка «Отменить». Если процент неизвестен — индикатор без выдуманного процента/времени. Нет зависшего окна, скрытого консольного лога вместо прогресса или фиктивного успеха.

Отмена прекращает операцию безопасно, не меняет источники и не публикует частичный результат. Во время атомарного финального шага явно показать «Завершаем безопасное сохранение», не обещать мгновенную отмену, если она уже небезопасна. Повторный клик не запускает параллельную сборку; после отмены можно изменить выбор и повторить проверку.

Основной результат — короткое резюме и действие:

| Ситуация / внутренний статус | Текст для игрока | Следующее действие |
|---|---|---|
| Проверка завершена, нет blockers | «Проверка файлов пройдена. Можно создать отдельный мод» | «Создать объединённый мод» только при пройденных package gates; рядом «Работу механик нужно проверить в игре» |
| Текущий read-only прототип | «Анализ завершён. Создание мода в этой версии ещё недоступно» | «Посмотреть результат»; никакого «Готово к установке» |
| `conflict` | «Эти моды меняют один участок по-разному» + названия | «Изменить выбор», «Показать проблему»; нет молчаливого выбора победителя |
| `no_base` | «Не удалось подтвердить оригинальные файлы этой версии игры» | «Выбрать папку оригинальных файлов», «Проверить снова» или справка; нет выдуманной базы |
| `native_plugin_review_required` | «Мод содержит дополнительный исполняемый плагин. Автоматическое объединение пока недоступно» | Назвать мод, предложить изменить выбор; не копировать DLL и не запускать её |
| `unsupported_binary` / `needs_review` | «Этот тип изменения пока нельзя безопасно объединить» | Назвать моды/ресурс, изменить выбор; не предлагать «продолжить всё равно» |
| `validation_error` / `encoding_conflict` | «Не удалось проверить получившийся файл. Сборка не создана» | Показать участников, повторить после изменения выбора, сохранить диагностику |
| `tool_error` | «Не удалось выполнить встроенную проверку. Сборка не создана» | «Повторить», справка/диагностика; без ручной установки зависимостей и консольных команд |
| `input_error`, нет доступа, изменились файлы | «Папка недоступна или файлы изменились. Проверьте расположение и повторите» | Системный выбор папки / повторное сканирование; старый результат недействителен |

Статус всегда передаётся текстом и значком, не только цветом. Код ошибки, путь ресурса, хеши, версия инструмента, diff и логи — в необязательных «Подробностях», не вместо человеческого объяснения. Не называть `clean` гарантией совместимости игры/мультиплеера. Не обещать функцию, которую текущая сборка не реализует.

## 5. Создание и результат

- Показать имя будущего мода, состав выбранных модов и безопасное место сохранения. Изменить место можно диалогом папки; нельзя выбрать исходники/игру/SDK/Workshop в обход managed-output политики.
- Перед записью — явное действие «Создать объединённый мод» и повторная проверка входных хешей. Запись только в отдельный staging/managed output с atomic publish и сохранением предыдущей рабочей версии при ошибке. Отмена/ошибка не портит предыдущую сборку.
- После подтверждённого успеха: «Объединённый мод создан», «Открыть папку», «Как включить в игре». Различать проверку, создание пакета и его включение — это не один статус.
- Инструкция включения короткая и графическая/текстовая для подтверждённой игровой платформы: отключить исходные заменённые моды, включить объединённый штатным меню и перезапустить игру. Не редактировать mods.xml и не включать моды/игру автоматически.
- «Как вернуть исходные моды» доступно из того же окна. Удаление/восстановление касается только собственной сборки, требует подтверждения; исходники и сохранения не удаляются.
- «Сохранить отчёт» открывает системный диалог. Отчёт редактируется от личных путей по умолчанию, не отправляется автоматически; raw JSON необязателен для понимания результата. Перезапись/назначение подчиняются безопасной файловой политике, не маскируются UI.

## 6. Качество и доступность

- Русский понятный текст, единая терминология; внутренние идентификаторы не попадают на главные кнопки. Строки отделены от логики, чтобы поддержать локализацию позже без переписывания экранов.
- Основные действия доступны клавиатурой с видимым фокусом и корректным порядком Tab; элементы и ошибки имеют доступные имена для экранного диктора.
- Масштаб интерфейса 100–200% и системный масштаб шрифта не обрезают основные действия; длинные названия и ошибки переносятся/раскрываются. Для текста — контраст не ниже 4.5:1; состояния не зависят только от цвета.
- Пустой список, нет игры, нет сети, ошибка доступа, конфликт, отмена, обновление Workshop и повторный запуск проверяются как обычные сценарии, не аварийные исключения.
- После изменения модов/версии игры приложение не использует прошлый результат молча. Отсутствие сети не мешает работе с уже установленными входами и компонентами; приложение не скачивает SDK/чужие моды автоматически.

## 7. Приёмка первой пользовательской версии

1. Чистые поддерживаемые Windows/macOS без установленного Python/Git/Lua и developer tools: скачать готовую сборку, открыть и выполнить основной сценарий в окнах. Нет обязательного терминала, всплывающей консоли или ручной настройки окружения.
2. Автопоиск/ручной выбор папки, выбор модов, проверка, конфликт и безопасный отказ, экспорт, отмена и повторный запуск покрыты GUI tests. Для создания — synthetic filesystem e2e и отдельный подтверждённый игровой smoke; одно не заменяет другое.
3. Один пользователь, не участвовавший в разработке, проходит сценарий по пользовательским экранам/справке без команд и подсказок разработчика. Фиксируются затруднения; найденные тупики исправляются до релиза.
4. UI не позволяет обойти engine blockers; смена выбора или источников аннулирует план, отсутствующая упаковка не имеет активной кнопки создания. Доступность и безопасное восстановление проверены на обеих ОС.
5. В поставку включены проверенные версии runtime/backend/validator, notices/лицензии; подпись/проверка доверия ОС учтена. Не предлагать обход Gatekeeper/защит Windows командами или отключением защиты.

До выполнения этих gates приложение не объявляется готовым для обычных игроков. Текущее CLI-ядро остаётся техническим промежуточным результатом, а не альтернативой обязательному GUI.

## 0.4.0b1: подготовленный запуск

Одна дополнительная настройка в существующем меню — «Запускать игру при открытии»,
по умолчанию выключена. Запуск только после успешной подготовки выбранного набора;
отказ отменяет автозапуск. При override warning окно остаётся открытым после запуска.
